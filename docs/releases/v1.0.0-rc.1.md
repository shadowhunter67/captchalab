# CaptchaLab v1.0.0-rc.1

A release candidate. It adds no product scope: this release is an audit and a freeze of behavior before 1.0. If it stays stable, the same code becomes 1.0.0; a blocker would produce an rc.2.

## Release candidate scope

- No new CAPTCHA family, no classifier v2, no new schema, no backend, database or cloud.
- A review of everything changed since `v0.11.0-beta.1`, a repository and secret scan, a link and anchor crawl of every public page, and a refresh of product-facing wording (status, security policy, limitations) that still said alpha or beta.
- New regression tests: a crawl that fails on any broken internal link or missing `#anchor`, and an Evaluation sweep that fails on any `NaN` or `Infinity` for any mix of labels and classifier readings.

## What did not change

- `behavioral-baseline@1` (the classifier rules, pinned by checksum tests).
- `captchalab-labeled-dataset@1` (the dataset format) and the import rules.
- The Evaluation formulas, the minimum-sample rule and the Threshold Sandbox (which still works only on a copy).
- Challenge verification, and the privacy model.

## Stability status

- Full automated regression in Chromium; a targeted smoke suite in Firefox and WebKit on every CI run (see Browser coverage).
- Stale-run protection is tested for Memory, Audio, Proof of Work, Proof of Space and Hybrid (a new challenge, a variant, difficulty or seed change, or unmount never lets an old run touch a new one).
- Audio no longer hangs on a device with no audio output: it reports that audio could not be started and points to the alternative challenge.

## Browser coverage

- **Chromium:** full regression (functional, privacy, accessibility structure, mobile widths, link crawl).
- **Firefox and WebKit:** targeted smoke of the main paths (Slider, Drag & Drop by keyboard and pointer, Text, Audio, Memory, Proof of Work, Proof of Space, Hybrid, Browser Capability, Dataset, Evaluation). This is not the full suite.
- Real Safari and mobile browsers are not automated. Playwright's WebKit build on Windows has no Web Audio, so there Audio is checked for its clear "not supported" message rather than for sound.

## Accessibility status

- Drag & Drop can be finished with the keyboard alone, with a pointer, or with both; Verify is blocked while a keyboard selection is pending.
- Every public page is checked for duplicate ids, ARIA references with no target, and horizontal overflow at 360-400 px. Status changes are announced in live regions.
- This is not a WCAG certification, and the keyboard flows are not checked with every screen reader.

## Privacy guarantees

- Raw interaction data stays in the browser tab. Nothing is uploaded, no analytics, no backend.
- No persistence: the dataset and experiments are in memory; exports and imports are user-triggered and local.
- Typed letters and digits are never recorded, only the class of the key; the keyboard Drag & Drop flow records only Enter, Space and Escape.
- Audio uses no microphone and no device enumeration. Browser Capability reports yes or no per API and measures no duration, makes no hash, score or identifier.
- `completionTime` and event timestamps describe the person's own session on the page, not the device.

Details: [privacy](../privacy.md).

## Known limitations

See [limitations](../limitations.md) and [technical debt](../technical-debt.md). In short:

- The classifier is hand-written; labels are user-provided; there is no verified human population dataset.
- MatchKey, Tile Game, Proof of Space, Browser Capability and Proof of Work have no deep classifier support.
- Firefox and WebKit run only the smoke suite; the Drag & Drop keyboard flow is not checked with every screen reader.
- Audio has one voice; Memory has no replay; Proof of Work and Proof of Space run on the main thread in bounded slices.

CaptchaLab is an educational and research platform. It is not a bot detector, not a production anti-bot system and not a replacement for any commercial CAPTCHA.
