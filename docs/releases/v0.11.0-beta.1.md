# CaptchaLab v0.11.0-beta.1

Stabilization only: no new CAPTCHA family, no classifier change, no schema change.

## Highlights

- **Drag & Drop works with the keyboard alone.** Shapes and drop areas are buttons: Enter or Space selects a shape, Enter or Space on a drop area places it, Escape unselects, and selecting a placed shape corrects it. The keyboard uses the same placement rule and verifier as a drag (an occupied area sends its shape back), shows a visible "selected" state, and announces selection, placement and cancel in the status line. Pointer and touch behavior are unchanged and their tests pass. Only Enter, Space and Escape (with the shape or drop-area name) are recorded.
- **Firefox and WebKit smoke suite.** `e2e/cross` runs the main paths in Chromium, Firefox and WebKit on every CI run; the full regression stays in Chromium. This is targeted coverage, not full cross-browser coverage.
- **Audio.** When a browser has no Web Audio, or the device never starts audio output (for example no audio device, where `AudioContext.resume()` never settles), the page now says so and keeps the alternative challenge, instead of a generic load error or hanging on "Loading audio...". Found by the Firefox smoke run on a headless Linux runner.
- **Proof of Work / Proof of Space.** The runner refuses a malformed challenge before doing any work (the same check the verifier uses); stale runs after Start then New challenge, a difficulty change or a seed change never touch the new challenge (tested).

## Unchanged on purpose

`behavioral-baseline@1`, the dataset format, the Evaluation math and the Threshold Sandbox. Browser Capability still reports capability booleans only.

## Known limits

See [limitations](../limitations.md): the classifier is hand-written, labels are user-provided, browser coverage beyond Chromium is a smoke suite, and the Drag & Drop keyboard flow is not checked with every screen reader.
