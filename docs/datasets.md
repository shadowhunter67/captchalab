# Labeled datasets (v0.8)

A local, in-memory collection of sessions, each with a **label a person gave it**. It prepares the data that a later evaluation step will need. It computes no accuracy and does not touch the classifier.

Route: `/experiments/dataset`. Code: `apps/web/lib/dataset/` (`records.ts`, `format.ts`, `store.ts`), `features/dataset/DatasetPage.tsx`, `components/dataset/AddToDataset.tsx`.

## The two ideas that must stay apart

| | What it is | Who sets it | Can it change the other? |
|---|---|---|---|
| **Label** (`human`, `synthetic`, `unknown`) | What a person says about a session | The user (or CaptchaLab, for sessions it generated) | No |
| **Classifier reading** (`human-like`, `synthetic-like`, `uncertain`) | What `behavioral-baseline@1` reads from the session's signals | The classifier, recomputed from the session | No |

A record may legitimately say *label: human* and *classifier: synthetic-like*. That disagreement is the data a later evaluation needs, so neither side is ever edited to match the other. The classifier function takes the signals and nothing else; no label reaches it, and a test checks that.

## Labels

- A **recorded** session enters as `unknown`. Recording an interaction does not make it a human one; the user may set `human` if they know where the sample came from.
- A session **generated by CaptchaLab** enters as `synthetic`, with its provenance (profile, `synthetic@1`, seed). While it is unchanged in this tab its label is **locked**.
- An **imported** record keeps the label the file declares, after validation. It is shown as a *user-provided label*, never as verified ground truth. An imported record is no longer "generated here", so its label can be edited.
- There is no `bot`, `verified-human`, `malicious` or `legitimate`.

## Source is not label

Each record has a `source`: `recorded` or `synthetic` (how the session was made) and an `imported` flag (it came from a file; a file proves nothing about who made it). The page shows both, for example *Source: Imported (recorded) / Label: Human*. Summary buckets: Recorded, Synthetic, Imported.

## Where records come from

Always an explicit click, never automatic: **Compare** (add my session / add the synthetic sample), **Experiments** (per session, *Add to dataset*), **Builder** (add this attempt). The challenge definition (CAPTCHA, variant, difficulty, seed) is kept with every record, so the sample can be understood and regenerated. The Invisible demo is not a CAPTCHA and is not added. Proof of Work is excluded from behavioral datasets (its measurements describe computation, not an interaction).

## Lifecycle

The dataset lives in this tab's JavaScript memory (a module-level store shared by the pages of the tab). It is **not** written to localStorage, IndexedDB, cookies or a server, and it is not sent anywhere. Reloading or opening another tab starts empty. Unexported changes are flagged and the browser asks before the page is left. Limits: 500 records and 300,000 events in total.

## File format: `captchalab-labeled-dataset@1`

```json
{
 "schema": "captchalab-labeled-dataset",
 "version": 1,
 "records": [
  {
   "schemaVersion": 1,
   "id": "d1",
   "challenge": { "format": "challenge-definition", "version": 1, "captcha": "checkbox", "...": "see data-formats.md" },
   "source": { "type": "recorded" },
   "label": "human",
   "context": {},
   "passed": true,
   "note": "left hand",
   "session": { "schemaVersion": 2, "id": "...", "captchaId": "checkbox", "startedAt": 0, "durationMs": 2400, "events": [], "inputModality": "mouse" },
   "features": { "version": "behavior-signals@1", "sourceSchema": "checkbox@1", "values": { "reactionTime": 1000, "interClickCv": null } },
   "classifier": { "version": "behavioral-baseline@1", "result": "uncertain" }
  }
 ]
}
```

- **Required** per record: `schemaVersion`, `id`, `challenge`, `source`, `label`, `session`, `features`. **Optional**: `context` (only where the CAPTCHA needs one: slider, drag-drop, rotation, memory), `passed`, `note` (plain text, 200 characters), `classifier`. A synthetic `source` also carries `synthetic: { profile, generator, seed }`; a recorded one must not.
- `null` in `features.values` means *not measurable* and is never turned into 0.
- Export is deterministic: records keep their order, event fields are written in a fixed order, and there is no timestamp (the wall-clock time of the interaction is exported as `startedAt: 0`).
- The existing formats (`challenge-definition@1`, `interaction-session@1`, `experiment-bundle@1`, `experiment-summary@1`) are unchanged and still read. A dataset file is not one of them and they are not datasets.
- Compatibility: strict like the others. An unknown field is an error; another envelope `version` is rejected; a record with another `schemaVersion` is rejected as a record.

## Import: untrusted by default

`parse → envelope → version → per record: structure → CAPTCHA/plugin → challenge definition → session (the same reader every format uses, including the Memory recall-clock check) → provenance → recompute signals and classifier → accept or reject`.

- The **envelope is all or nothing** (wrong schema or version, hostile structure, too many records, size, depth). **Records are judged one by one**: valid ones are appended to the current dataset, the others are listed with a reason (*37 imported, 2 rejected*).
- **Signals and the classifier reading are always recomputed**; what the file claims is kept only as information and any difference is reported. **The label is never recomputed.**
- A record that claims `synthetic@1` provenance is **regenerated** from its challenge, profile and seed and must match exactly; a forged session is rejected (*Synthetic provenance inconsistent*), and a regenerated-exactly session cannot carry the label `human`. Another generator version cannot be regenerated, so it is accepted with a warning and marked unchecked.
- A typing session (`text-input`, `math-input`, `audio-input`, `sequence-input`) may hold only key classes and control keys. A record that says which key was typed (`KeyA`, `Digit5`) is rejected; this applies to every session reader.
- A taken id gets a new local id (`from → to` is reported); nothing is overwritten.
- Limits: 25 MB per file (checked before reading), depth 16, 2 million values, 20,000 events per session, 500 records, 300,000 events in the dataset (a dataset can hit the value limit before the record limit when its sessions are long).
- Nothing in a file is evaluated; text fields are plain text and rendered as text.

## Privacy

Local-first: no upload, no analytics, no automatic persistence. **An exported file may contain interaction event data** (coordinates and times; keys only as classes, never the characters typed), plus any note you wrote: do not put personal information in notes, and check a file before sharing it. Audio records hold no sound: the microphone is never used.

## What this is not

Not an evaluation: no accuracy, precision, recall, F1, ROC or AUC, and no "correct/wrong classification" wording. The summary only counts labels, sources, CAPTCHAs, variants, difficulties, the *current classifier's outputs* (apart from the labels) and how complete each signal is. A user-provided label is not verified ground truth.
